# 報表匯入契約

[返回 README](../../README.md) · [操作步驟與排錯](user-guide.md) · [合成資料練習](demo-and-screenshots.md)

## 操作

在「系統設定 → 匯入報表」選擇一份或多份 `.xlsx`：

- 歷史／預算：辨認每日業績明細、月彙總實績與月預算，可放在同一檔不同表格，或分成多檔。
- 當月 SHPB：使用原本 `/upload/current-month` 的每日訂單用途。
- 監控 SHPB：需要原本監控所需的完整欄位，寫入每日監控實績。兩種 SHPB 用途不會自動互相複製。
- 檔名不決定資料類型、年份或優先順序。舊「同步資料」會檢查資料目錄內所有非暫存 `.xlsx`，不再任選一份。可在設定頁選擇要匯入的檔案，避免把匯出結果一起同步。
- 「預覽歷史／預算匯入」回傳 JSON：來源雜湊、工作表／標題／來源列／欄位置、辨認類型、年月、指標單位、筆數、範圍與尚待處理的衝突。預覽不寫入；真正匯入仍在交易內重新檢查鎖定與重疊。

## 明確的涵蓋範圍

月份使用逗號分隔的 `YYYY-MM`。

- `observed_months`：月彙總實績確實涵蓋的月份，必填。模板裡未來月份的零值不能自行當成已發生實績。未選月份不寫入；不存在於資料的選擇會拒絕。預覽可以先不填，列出可辨認的年月供判斷。
- `complete_months`：只有確認提供該月所有客戶、商品、交易的完整快照時才填。該月舊每日資料會完整取代，包含新檔未列出的列；其他月份保留。歷史明細取代同月份的當月資料時，清除與寫入在同一交易完成。
- 不填完整月份時，新的、不重疊客戶／商品範圍可新增；相同交易多重集合可安全重送；不同且重疊的每日資料會停止。保留真正的相同交易，不以值相同就刪掉重複交易列。
- 多個每日表格涵蓋相同客戶／商品／月份時，必須明確勾選它們是互不重複的分割檔（`daily_partitions=true`），否則停止。
- 月資料以年月、客戶、商品、指標為鍵。預算與月實績只更新提供的指標鍵，不清除整年或其他客戶。缺少預算指標保持未提供（NULL），不捏造零值。
- 同一完整檔案位元組重送會先略過重複檔案。不同檔案重疊的月指標預設拒絕；明確勾選 `deduplicate_monthly=true` 後才略過完全相同的月指標，數值衝突仍拒絕。
- 月實績與每日資料同範圍不相加，也不猜優先權；請先選定來源／處理既有資料。已結月月份不能由任何匯入路徑覆蓋。

## 支援的辨認範圍

- 工作表名稱、順序、標題上下／左右位置、欄位順序、檔案數不固定。
- 支援一張表不同上下區塊及不相交左右區塊；表內空白列不會截斷資料。標題名稱採現有精確欄名，不使用模糊猜測、去前綴或全域去空白。
- 不支援任意轉置、合併標題或缺失欄位的猜測。可唯一辨認才繼續；否則提供位置與原因。
- 每檔最多 25 MiB、解壓後 200 MiB、50 個工作表、50 萬個掃描儲存格與 100 個表格；每批最多 50 檔及 100 MiB。超限明確報錯。
- 只有完全空白列，及 SHPB 中日期／客戶／產品皆空、產品簡稱精確為「每日總計」的摘要列可忽略。其他缺失關鍵值、日期錯誤或異常數字不會悄悄刪除／歸零。
- 公式錯誤與無快取公式拒絕。識別碼字串保留前導零；數值識別碼使用補零格式時要求改為文字，避免改變識別碼。身份欄位前後空白要求明確修正。既有系統會把數字文字的 `.0` 尾碼當成別名，因此新匯入遇到這種有歧義的商品碼會要求提供正式代碼，不會靜默改鍵；原有品項設定規則保持相容。

## 日期、年分與指標

- 日期接受整數／文字 `YYYYMMDD`、文字 `YYYY-MM-DD`、或 Excel 原生日期儲存格。裸 Excel 日期序號、無效日期、小數日期不猜測。日期不可含非零時間或時區。
- 月欄接受整數／文字 `YYYYMM`，或 `1..12` 加上明確年份。預算可用 `budget_year` 提供年份；表內年與欄內年以及指定年須一致。檔名年份不是權威。
- 預算保留「02預算總量」「04預算總額」「07預算S總量」三種指標；只排除既有模板的四種明確實績／達成率標籤。預算金額稅別標為來源定義，不做稅額換算。
- 月實績需要五種報表指標：普通量、S 量、含稅金額、未稅金額、折後業績額。可以分檔提供，但整批每個年月／客戶／商品必須齊全。
- 月實績保存在 `monthly_actual_facts`，由既有上月實績、六個月趨勢與月底檢討的同期／客戶／產品分析讀取。S 量只與 S 量比較；普通量與不同金額口徑不混合。
- 月資料不產生虛構訂單日、最近訂單單價或叫貨週期。只有月資料的品項不會冒充每日預估列。`GET /history/monthly?year=2025&month=1` 可查看月資料與不可用的每日能力。

## 安全性與相容性

`import_parser` → `import_normalization` → `import_service` 是共同流程。既有三個 HTTP 匯入路徑、ETL CLI 與 Excel 相容載入器皆使用它。

全批解析與驗證先於寫入。寫入使用 SQLite `BEGIN IMMEDIATE`、參數化 SQL／`executemany`；不以 pandas `to_sql` 寫入。事實資料、涵蓋範圍清除、來源收據在同一交易，失敗完整回滾。結月也在取得寫鎖後確認狀態與彙總。Cache 只在成功回傳後失效。

來源收據保存檔名、內容雜湊、工作表與儲存格位置；不保存或修改原始工作簿。重送相同語意且目前值未變，不增加交易列或收據。既有歷史／當月表若已重疊，讀取時明確報錯，避免 `UNION ALL` 重複計算。

刻意改變的舊行為：不再猜檔名年份、任選檔案、丟掉壞日期、把壞數字變零、無條件整年／全歷史刪除、在主交易外 best-effort 清除當月資料，或讓不同重疊快照無聲覆蓋。

## 月資料的使用範圍與身份核對

月彙總匯入成功後直接開啟「月彙總實績」頁（`/history/monthly/view`），可切換已匯入月份、查看客戶／商品列及五種指標的各自合計。此頁不混入每日來源，也不把沒有資料的月份表示成零。導覽列可隨時再次開啟；原有 `/history/monthly` JSON 介面保留。

已有真正每日紀錄的預估列，其去年／今年各月數量與含稅金額、去年同期數量，會讀取相應月彙總。只有月資料的品項仍不建立每日預估列，日預測、訂單日期、單價、叫貨週期不可用；請使用月彙總實績頁。這一版完成月分析的匯入閱讀流程，並未宣稱月資料可支援完整日預測功能。

有提供客戶代號時，代號與簡稱的對應會保存，且每次匯入在寫入交易內對照既有證據。同一簡稱改成另一代號即停止；舊資料只有簡稱而沒有可驗證代號時，也需先明確解決對應，不能自行把新代號綁上舊實績。此版本不提供自動合併或身份修正工具。原本僅有簡稱的來源仍沿用既有名稱鍵，不聲稱能從缺少的代號辨認不同客戶。

每日來源關聯使用「用途、年、月、客戶、商品」範圍鍵。追加不重疊範圍保留先前來源收據；完整月份取代才在同一交易清除該月舊來源關聯。歷史取代當月資料時，當月來源關聯也一起退休。
