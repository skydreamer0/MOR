# 匯入與日常操作指南

[返回 README](../../README.md) · [精確格式契約](workbook-import.md) · [假資料練習](demo-and-screenshots.md)

## 先選對用途

在「系統設定」展開「匯入報表（單檔或多檔）」。同一表單有三個提交用途：

| 按鈕 | 來源 | 寫入用途 |
| --- | --- | --- |
| 匯入歷史／預算 | 每日歷史明細、月彙總實績、月預算 | 歷史分析／預算；可同批多檔、多表格 |
| 匯入當月 SHPB | SHPB 每日出貨欄位 | 當月交易來源 |
| 匯入監控 SHPB | 完整監控 SHPB 欄位 | 每日監控實績；一批只能有一個月份 |

當月與監控 SHPB 是不同用途，不會自動互相複製。「預覽歷史／預算匯入」只對應第一種用途，不是所有按鈕共用的匯入確認頁。

## 準備工作簿

使用 `.xlsx`，保留原始檔，另存修正副本。工作表名稱、先後順序、標題位置及欄位順序可以不同；一張表可含上下區塊或不相交的左右區塊。空白資料列不會提前截斷整張表。

辨認靠精確欄名，不靠檔名。請保留「標  題」中間兩個空白；不要自行刪除欄名前綴。任意轉置、合併標題及缺欄猜測不支援。資料無法唯一辨認時，先修正來源格式。

### 每日歷史明細

必要欄位：`年`、`月`、`日`、`客戶簡稱`、`商品號`、`商品簡稱`、`銷+贈S量`、`單價NT(淨)`、`含稅總額(淨)`。

年、月、日分欄且必須構成有效日期；例如 `2025`、`1`、`15`。數量使用 S 量，單價與金額依來源欄位保留，不由月資料反推。

### 月彙總實績

共同欄位：`客戶簡稱`、`商品號`、`標  題`，加一個或多個月份欄位。每個年月／客戶／商品需要以下五種指標，允許分在不同檔案，但同批必須齊全：

| 「標  題」精確值 | 顯示口徑 |
| --- | --- |
| `01銷+贈量` | 普通量 |
| `02銷+贈S量` | S 量 |
| `03銷含稅總額` | 含稅金額 |
| `04銷未稅總額` | 未稅金額 |
| `05折後業績額` | 折後業績額 |

月份欄可寫 `202501`；或寫 `1` 並提供 `年` 欄。只有月實績時，使用帶年份的月份欄最容易核對。實績模板的未來月份即使填了零，也不代表已發生；只有你明確指定的「月實績確實涵蓋月份」會寫入。

### 月預算

共同欄位同月實績；可提供以下指標：

| 「標  題」精確值 | 用途 |
| --- | --- |
| `02預算總量` | 普通總量，獨立保存 |
| `04預算總額` | 金額目標，稅別依來源定義 |
| `07預算S總量` | S 量目標，供 S 量比較 |

未提供指標保留為缺值，不補零。月份可寫 `202601`，或寫 `1` 並由 `年` 欄／「預算年份」提供年份；所有已提供年份必須一致。檔名中的年份不採用。

### SHPB 每日出貨

當月用途必要欄位：`出貨日期`、`客戶簡稱`、`產品`、`產品簡稱`、`銷售數量`、`贈品數量`、`銷貨淨價`、`含稅淨額`。

監控用途還需要：`客戶代號`、`折後業績`、`發票編號`、`出貨單號`、`單別`、`業績屬性`。這些欄位必須存在；代號／發票等文字欄允許空白時，也不能藉此推論已驗證身份。

出貨日期接受 `20260115`、文字 `2026-01-15` 或 Excel 原生日期。裸日期序號、`2026/01/15` 字串、帶非零時間或時區、無效日期不接受。每日數量由銷售數量加贈品數量組成。

### 數字與身份

- 數字空白不等於零；異常字串、無限值、公式錯誤及沒有快取結果的公式會被拒絕。
- 代號有前導零時，用文字儲存，例如 `0001`，不要依賴數字顯示格式補零。
- 代號／客戶名稱的前後空白要明確修正。商品文字帶有會被舊規則改鍵的 `.0` 尾碼時，需提供正式代號。
- 有提供客戶代號時會比對並保存名稱與代號證據。同名異碼、或舊資料只有名稱而缺少可驗證對應時，先停下核對；目前沒有自動身份合併或修正介面。

## 預覽再匯入歷史／預算

1. 選取檔案。單一工作簿可含不同用途的表格，多檔也可以一起選取。
2. 按「預覽歷史／預算匯入」，閱讀 JSON。`tables` 是各表格與來源位置，`counts` 是辨認後筆數，`unresolved` 列出待解決問題。月資料的筆數是指標欄值數，不等於客戶／商品列數。
3. 回設定頁確認檔案仍在；若瀏覽器清空檔案欄位，重新選取。填寫必要年份與確實涵蓋月份。月份格式為 `YYYY-MM`，多個月份用逗號分隔，例如 `2025-01,2025-02`。
4. 再預覽，核對來源、月份及筆數。`can_commit=false` 時先處理 `unresolved`；`true` 也不代表已寫入或保證稍後提交一定成功。
5. 按「匯入歷史／預算」。提交時會在交易內重查結月鎖定、身份與重疊；成功才一起保存並更新快取。
6. 月實績會導向「月彙總實績」，選擇已匯入月份，核對五種指標及客戶／商品列。若該月沒有資料，頁面會明示沒有匯入資料，不把它當零。

預覽目前是 JSON 文件，不是可勾選資料列的試算表。沒有額外的逐列修正或自動客戶合併工具。

## 決定新增、重送或取代範圍

### 只新增不重疊資料

「完整取代的每日月份」留白。不同客戶／商品／月份範圍可新增；與既有資料同範圍且內容不同的每日快照會停止，避免不明確的相加或覆蓋。

### 重送相同資料

完全相同檔案會先略過重複檔案；相同語意且現有值未改變的重送不增加每日交易或收據。真正存在的兩筆相同交易仍保留，不會只因數值相同就刪掉一筆。

不同檔案若重複提供相同月指標，預設停止。只有確認是同一筆月指標時，勾「略過相同月實績／預算鍵且數值完全相同的重複資料」；數值不同仍拒絕。這不是衝突自動取最新值。

### 串接分割每日檔案

多個每日表格若涵蓋相同客戶／商品／月份，必須先確認交易互不重複，再勾「這些每日表格是互不重複的分割檔，可以串接交易」。這個宣告由你確認，不是系統已替你驗證交易沒有重複。

### 完整取代某月每日資料

1. 備份目前資料，確認該月尚未結月。
2. 確認這次檔案涵蓋該月份全部客戶、商品、交易。
3. 在「完整取代的每日月份」填該月，例如 `2026-01`，再依正確用途提交。

結果：該用途該月的舊每日範圍被取代，新檔沒有的舊列也會移除；其他月份保留。歷史來源取代相同月份的當月來源時，清除與寫入一起完成。

月實績／預算則以年月、客戶、商品、指標為鍵，只更新本次提供的鍵，不整年清空。月實績與每日來源同範圍不可疊加；請先決定保留哪個來源，不能以完整月份選項規避衝突。

## 閱讀月分析

從導覽列開啟「月彙總實績」，或前往 `/history/monthly/view`。頁面提供已匯入月份連結、客戶／商品列及各指標自己的合計；普通量、S 量、含稅／未稅／折後金額分開閱讀。

只有月資料的品項不會出現在每日導向的預估列，也無法推算最近訂單日、叫貨週期或單價。已有每日預估列的品項，去年／今年各月數量、含稅金額及同期比較可讀取相應月實績。不能把「月分析可見」解讀為「完整日預測已可用」。

需要機器可讀結果時，`/history/monthly?year=2025&month=1` 提供 JSON；這與 HTML 頁面是不同入口。

## 調整預估與結月檢討

1. 有每日資料後，在 `/forecast` 選擇目標年月，檢查數量、備註與排除項目，儲存所需草稿／定稿快照。
2. 匯出後核對「預估總覽」「預估明細」「排除明細」三個工作表。
3. 在 `/monitor/products` 使用完整監控 SHPB 追蹤當月實績與月底推估。
4. 月底確認資料後再使用結月操作；結月後同月份不可由匯入覆蓋。至 `/monthly-review` 查看實績、預估、預算與同期差異。

比較口徑：達成率為預估／目標 × 100，GAP 為預估 − 目標；上月指標使用上月實績／預算。產品數量目標以 `07預算S總量` 對比 S 量；普通總量不混用。總覽優先採 `04預算總額`，舊資料缺金額時才用量 × 最新單價估算；缺預算列列在資料檢核，不用來放大達成率分子。

## 排除匯入問題

| 看到的問題 | 下一步 |
| --- | --- |
| 缺少／無法辨認欄位 | 依本頁精確欄名修正；檢查「標  題」空白、任意轉置或合併標題 |
| `Missing/conflicting year` | 檢查月份欄、`年` 欄、預算年份是否一致；不能靠檔名補年份 |
| `blank is not zero` 或無效數字 | 核實來源，明確填數字；若是真正缺資料，不要為通過驗證隨意填零 |
| 無效日期 | 使用支援日期格式，檢查曆日是否合法；保留原始日期證據 |
| 要求月實績涵蓋月份 | 填已發生且確實涵蓋的月份；不存在於檔案的月份也會拒絕 |
| 每日重疊／月指標衝突 | 確認是重送、互斥分割還是完整快照；不要盲目勾選選項 |
| 客戶身份衝突／未驗證的舊名稱 | 核對正式客戶代號與名稱，交維護者處理；不以改名稱繞過檢查 |
| 月份已結月 | 停止覆蓋，交由負責人核對；匯入頁不提供解除鎖定 |
| 匯入成功但預估頁沒有月資料品項 | 到月彙總實績頁；只有月資料不會產生每日預估列 |
| 檔案超限 | 每檔 25 MiB、解壓後 200 MiB、50 表、50 萬掃描格、100 個表格；每批 50 檔／100 MiB。移除無關空白格式區或合理分批，保留完整指標與範圍 |

錯誤可能包含檔名、工作表或儲存格位置。回報問題時附版本、操作步驟與經去識別的錯誤；不要把完整工作簿、客戶名稱、公司數字或資料庫放到公開 issue。

## 備份、回滾與重新啟動

**失敗交易自動回滾；成功交易沒有一鍵復原按鈕。** 來源收據用來追查檔名、雜湊、工作表與位置，不保存整份工作簿，也不是可直接點選復原的版本庫。

- 大量匯入、完整月份取代或升級前，停止 MOR，備份實際使用的資料目錄與原始 Excel，保留當時版本。SQLite 若有 `-wal`／`-shm` 側檔也應保留一致的資料集合；不在寫入期間只複製單一 DB 當成可靠備份。
- 啟動失敗若顯示缺套件，使用 README 的同一個 Python 環境重跑 `-m pip install -r requirements.txt`，再啟動。不要刪除資料庫或原始 Excel。
- 還原是人工維護操作：先停程式、備份現況，再以相容版本與完整備份驗證。不要把不同備份中的 DB／側檔混合，也不要在仍執行的資料目錄直接覆寫。
- 練習或排錯使用獨立資料目錄，範例見[合成資料練習](demo-and-screenshots.md)。
